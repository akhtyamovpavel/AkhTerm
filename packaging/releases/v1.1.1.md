## Bug Fixes in AkhTerm v1.1.1

- **Prevent `OSC 8` Hyperlink & `OSC 7` Directory URI Truncation on Cyrillic `М` ([#62](https://github.com/akhtyamovpavel/AkhTerm/issues/62)):**
  - **Root cause:** Russian capital `М` (`U+041C`) encodes in UTF-8 as `0xD0 0x9C`, where `0x9C` coincides with the 8-bit ECMA-48 `ST` (*String Terminator*) control byte. When a TUI (`AGY`, `Claude Code`, `Codex`) emitted unescaped Cyrillic paths inside an `OSC 8` hyperlink (`\x1b]8;;file:///.../ПП_МФТИ_003...\x07`) or `OSC 7` directory URI, `libvte-2.91` terminated the OSC sequence mid-character at `М` and printed the remaining URI tail (`ФТИ_003...pdf`) into the terminal cells as raw text.
  - **Fix:** `OscStreamParser` (`src/terminal/osc_parser.rs`) now percent-encodes non-ASCII UTF-8 bytes (`>= 0x80` as uppercase `%XX`) on the fly at the PTY boundary for both `OSC 8` hyperlinks and `OSC 7` working-directory URIs across arbitrary PTY `read()` chunk splits, leaving already-escaped ASCII sequences (`%D0%9C`) and visible link labels untouched.
  - **Verification:** Covered by byte-split streaming unit tests, `resolve_link_target` / `decode_file_uri` local Cyrillic `file://` path checks, and a headless Broadway `libvte-2.91` PTY-tap integration test.

## Installation

### Ubuntu 24.04 & 26.04 (`amd64`)

```sh
sudo apt install ./akhterm_1.1.1-1_amd64.deb
```

### Fedora 41 & 42 (`x86_64`)

```sh
sudo dnf install ./akhterm-1.1.1-1.x86_64.rpm
```

### Portable Linux Tarball (`x86_64`, supports one-click in-app self-update)

```sh
tar -xzf akhterm_1.1.1_linux_x86_64.tar.gz
install -m 0755 akhterm-1.1.1-linux-x86_64/akhterm ~/.local/bin/akhterm
```
